01

最终决策与适用范围

这是供后续研发使用的设计基线。本文中的表、业务接口、同步器与就绪协议均为平台拟实现内容，不代表当前项目已具备这些能力。

推荐实现：发布记录 + 自动同步 + HTTP 加速

  1. 管理层创建不可变发布清单及待加载记录，保存数字员工与能力版本的绑定关系。
  2. Mastra 运行层、工具网关启动时和运行中定期检查本环境需要的版本，发现差异后加载。
  3. HTTP 内部管理接口收到通知后立即唤醒同步器；通知失败也能由定期检查补偿。
  4. 发布服务确认指定服务范围内的运行层和网关均就绪，再原子切换生效指针。
核心边界：一次 HTTP 成功、一次数据库更新、一次 addAgent() 成功，都不单独等于发布生效。生效需要完整发布包就绪及明确的版本选择。

配置发布

工具描述、输入输出契约、已有适配器配置、Skill 内容、已支持的 Workflow 编排、数字员工绑定发生变化时，生成新发布版本并动态加载。无需为每个工具生成 .ts 文件。

代码部署

新增协议、特殊签名、自定义工作流步骤、工厂逻辑或运行依赖时，需要研发交付并部署执行代码。先满足运行能力要求，再发布引用这些能力的配置。

实例指一份运行中的服务进程：一台机器可以运行多个实例，一个实例也可以承载多个数字员工。数字员工数量与实例数量不是同一概念。

沿用总体架构中的管理层、接入层、Mastra、工具网关和目标系统边界。逻辑分工与物理部署分别设计。

03

发布时序与状态

创建候选版本 R8

复制编辑态配置，校验契约与依赖，固定 Tool、Skill、Workflow、策略及适配器版本；写入不可变清单和内容摘要。此时 R7 仍服务。

进入 PREPARING 并通知

记录本环境需要预加载 R8。通知发生在事务提交后；HTTP 请求只携带发布标识，不携带执行代码或目标系统密钥。

各组件拉取并预加载

运行层和网关分别构造本地配置。校验依赖兼容性，按拓扑顺序注册对象，整包可用后回报 READY。配置预加载不执行真实业务写操作。

汇总就绪并受控生效

首期要求指定单运行实例和网关均就绪。多实例时要求拟承接 R8 的服务范围全部就绪；未就绪实例不得接收 R8 请求。

原子切换生效指针

使用期望 generation 校验执行条件更新：R7 → R8，generation 加一。新运行由接入层选定 R8；同步通知不是生效指令。

保留旧版本并回收

已有运行继续用 R7。确认无活动、挂起或待恢复运行依赖后，再按留存规则回收 R7；回退前确保 R7 重新就绪。

发布状态 点击查看语义

PREPARING · 等待组件加载

R8 已持久化并列入期望加载集合；运行层、网关分别预加载。业务仍由 R7 承接，收到通知不代表已完成。

完整状态定义：DRAFT 为可编辑草稿；PREPARING 为候选版本预加载；READY 为目标服务范围已就绪；ACTIVE 为当前生效版本；RETIRED 为退出生效但按需保留；FAILED 为候选发布校验或加载失败。回退是把生效指针切回旧版本的一次新操作，并记录审计。

发布清单内容不可变，发布状态单独维护。组件加载状态另设 PENDING / LOADING / READY / FAILED，不与发布状态混用。ACTIVE 已生效后的实例故障影响服务就绪，不应改写成“候选发布失败”。

发布清单与数据模型

以下为建议的平台模型。标识在 tenantId + environment 范围内解析，引用必须指向明确版本，避免隐式 latest。

实体 / 建议表关键字段实现约束
工具版本 tool_versiontoolCode、version、description、input/outputSchema、adapterRef、identityMode、riskLevel发布后不可原地修改；执行代码保留在受控适配器中。
能力版本 skill / workflow_versioncode、version、内容或 definition、内容摘要、依赖引用Skill 内容固定版本；Workflow 固定图和组件依赖。
发布版本 employee_releasetenantId、environment、agentId、releaseId、manifest、manifestHash、status、createdBy清单不可变；内容摘要按约定的规范化字节计算；状态与内容分开。
环境目标 deployment_targetagentId、activeReleaseId、desiredLoadReleaseIds、generation、servingScope期望集合保留当前生效版、候选版及仍被运行引用的版本；切换用条件更新。
实例心跳 runtime_instancecomponent、instanceId、bootId、runtimeVersion、capabilities、lastHeartbeat每次进程启动生成新 bootId；超时实例的旧 READY 不作为当前就绪证明。
加载回报 instance_release_statusinstanceId、bootId、releaseId、manifestHash、status、loadedAt、errorCode按当前启动周期确认；只在整包可用后记录 READY。
发布操作 release_operationoperationId、requestId、type、releaseId、status、operator、error、timestamps支持重复请求关联、状态查询、发布与回退审计。
运行绑定 run_release_bindingrunId、tenantId、agentId、releaseId、manifestHash、state创建运行时固定；持久化恢复也使用原版本；保护仍被引用的旧版本。

05

HTTP 接口契约

以下路径是平台建议接口，不是 Mastra 现成的企业发布协议。运行端可通过 registerApiRoute() 接入内部路由；管理服务负责鉴权、持久化和操作状态。

接口提供方 / 调用方行为
POST /internal/releases/load运行层或网关 / 管理发布服务接受同步提示，幂等创建或复用本实例加载操作；返回 202，已就绪可返回 200。禁止在该接口直接激活发布。
GET /internal/release-operations/{id}运行层或网关 / 管理发布服务查询本实例加载状态；响应带 instanceId、bootId、releaseId 和内容摘要。
GET /internal/deployment-targets管理层 / 实例同步器按环境和租户拉取期望加载集合、生效指针和 generation；首期可轮询，后续增加 ETag 或增量查询。
GET /internal/releases/{releaseId}管理层 / 实例同步器在租户、环境范围内读取不可变清单及内容摘要，固定依赖引用。
PUT /internal/instance-release-status管理层 / 实例同步器幂等回报加载结果；服务身份必须与所报实例一致；重试回报不能重复激活。
POST /management/releases/{id}/activate管理层 / 授权发布操作方检查就绪、发布权限与 expectedGeneration，事务内更新生效指针并记审计；并发冲突返回 409。

内部访问约束：接口只允许授权管理服务调用，采用服务身份验证及环境 / 租户范围校验；请求中的 releaseId 仍需对照持久化期望状态验证。清单地址由受控配置解析，不接受任意 URL、源码或动态执行字符串。
06

同步器与对象注册

HTTP 触发

立即唤醒本实例同步器，缩短发布等待时间。通知内容是提示，实际目标从权威发布存储读取。

启动同步

建立新 bootId，拉取当前生效版本及需要保留的版本。加载完成后才允许承接相应版本请求。

周期同步

例如每 10 秒加随机抖动检查一次，失败采用退避。间隔为初始建议，需按发布时效和负载调优。

syncRelease() 逻辑骨架 伪代码，非可直接运行实现

async function syncRelease(scope, releaseId) {
  return locks.forRelease(scope, releaseId).run(async () => {
    const target = await management.readDeploymentTarget(scope);
    assertDesiredOrStillReferenced(target, releaseId);
    const release = await management.readImmutableRelease(scope, releaseId);
    validateManifestHashAndCompatibility(release);

    const key = versionKey(scope, releaseId, release.manifestHash);
    if (localCatalog.isReady(key)) {
      return reportReadyAgain(key, instanceId, bootId);
    }

    await reportLoading(key, instanceId, bootId);
    try {
      // 阶段一：构造、检查依赖，不允许业务入口使用半成品。
      const bundle = await factories.buildAndValidate(release);
      // 阶段二：所有对象使用版本化 ID / key，按依赖顺序注册。
      await registry.registerInDependencyOrder(mastra, bundle);
      await validateBundleUsable(bundle);
      localCatalog.markReady(key, bundle); // 整包就绪标记
      await reportReady(key, instanceId, bootId);
    } catch (error) {
      localCatalog.markUnavailable(key);
      await reportFailedWithRetry(key, safeErrorCode(error));
      throw error; // 发布服务不激活该候选版本
    }
  });
}

locks、management、factories、registry、localCatalog 和状态回报均为平台自建组件。此函数只负责加载，不负责修改生效指针。通知、定时和启动任务必须复用它。

对象配置如何变为运行对象Mastra 接入
Tool平台工具工厂编译契约，调用 createTool()；execute 使用已部署的网关客户端，捕获工具编码与版本。addTool(tool, versionedKey)；再明确加入该 Agent 的 tools。全局注册不等于授予全部 Agent 调用权。
Skill加载固定版本内容，使用 createSkill() 或受控版本化 SkillSource；脚本的执行能力及依赖另行管理。通过 Agent.skills 绑定，可按 RequestContext 解析；不假设存在 addSkill() 接口。
Workflow使用已部署工厂构造流程，或在受支持范围内加载 JSON 动态工作流；自定义执行步骤仍需代码交付。addWorkflow(workflow, key)；JSON 路径使用 addDynamicWorkflow()，当前为 Beta。
Agent平台工厂加载模型配置、指令及能力绑定，构造版本化 Agent；可动态解析 tools / skills / workflows。addAgent(agent, versionedKey)。新运行通过内部版本映射取得指定 Agent。
注册不是跨对象事务：不要假设多次 add*() 调用具备整包原子性。先构造并校验，使用版本化命名；只有整包 READY 才允许业务入口使用。失败产生的未完成对象应隔离并安全清理；Mastra 默认资源接口也必须内部化或按发布权限限制，不能绕过版本就绪检查。

依赖图中 Tool 引用其注册 key；动态 Workflow 的 Agent / 嵌套 Workflow 引用其内在 ID。统一映射版本化 key 与 ID，按依赖图排序，不能一律假设“所有 Tool → 所有 Workflow → 所有 Agent”；循环依赖在发布校验时拒绝。

07

生效、回退与运行固定

新运行选择版本

  1. 接入层验证调用方、当前用户及平台准入。
  2. 读取当前生效指针，固定 releaseId、manifestHash 和 generation。
  3. 创建 runId 与持久化运行绑定。
  4. 只路由到该版本已 READY 的实例。
  5. 服务端写入可信 RequestContext，执行指定版本。

回退与旧运行

  1. 确认目标旧版的对象、网关配置和代码依赖仍可用。
  2. 若已回收，先重新加载并获得 READY。
  3. 通过新的发布操作切回旧版，generation 继续递增。
  4. 当前运行维持原版本；紧急终止属于独立操作。
  5. 等待运行完成和恢复保留期后，回收无引用对象。
身份校验 + 选定 R8→R8 Agent→R8 Tool 包装→网关逐次授权→目标系统最终授权
版本固定的范围：一次运行固定 Agent、Tool、Skill、Workflow 及策略基线；系统当前权限、令牌有效性和紧急禁用仍在调用时判断。新的用户提问默认视为新运行，可使用新生效版；历史 conversationId 不自动锁定旧版。若业务要求整个对话固定版本，应另外定义会话版本迁移策略。
恢复边界：“已有运行保留 R7”不等于普通流式请求会在进程重启后自动恢复。需要跨重启恢复的长流程，必须持久化运行状态与 releaseId，并验证所用 Workflow / durable 机制及存储支持。挂起运行引用的版本和执行依赖不能提前删除。

网关收到可信服务身份、用户上下文、agentId、releaseId、toolCode、toolVersion、runId、traceId 后，核对发布绑定并逐次判权。浏览器和模型不能自行指定授权身份或目标令牌。

08

故障恢复与多实例

故障 / 竞争情形要求的处理对业务的影响
发布已保存，HTTP 通知失败实例周期拉取期望状态，发现差异后补加载；通知可重试。候选发布延后，R7 保持生效。
加载成功，HTTP 响应或 READY 回报丢失重复同步复用本地对象并再次回报；状态回报幂等重试。确认前不激活，避免误判成功。
实例重启 / 新增实例新 bootId，启动同步；重新校验当前版本可用性。未就绪实例不承接相应版本请求。
R8 部分对象注册失败整包标记不可用，记录错误并重试；隔离未完成对象。R8 不进入可服务集合，R7 继续服务。
R8 通知晚于 R9 到达读取最新期望状态；忽略已无需求的旧通知。同步不激活，生效用 generation 防并发冲突。迟到事件不能把生效版本退回 R8。
运行层 READY，网关未 READY候选版本保持等待；状态查询给出网关失败原因。不得激活会调用缺失网关配置的版本。
收到 R8 请求但本实例尚未加载受控等待或转发到 READY 实例；否则返回可重试错误。不能静默使用 R7 执行 R8 请求。
管理服务临时不可达已就绪版本可按既定业务鉴权规则继续服务；新发布停止。重启实例若无可验证配置则保持未就绪。配置故障不等于授权放开；网关授权依赖故障按其策略处理。
生效后实例或网关故障通过心跳、请求失败和实际就绪检查移出服务范围；补加载或扩容。历史 READY 回报不能替代当前可用性判断。

首期 · 单实例 HTTP

管理服务调用实例的内部地址，实例内同步器加载。启动同步和定期补偿一并实现。实例从管理 API 拉取数据，避免运行服务直接依赖管理数据库结构。

扩展 · 多实例通知

直接 HTTP 需要实例发现并逐一通知；调用一次负载均衡地址通常只命中一个实例。也可采用广播消息或配置订阅，保证每个相关进程能触发本地同步。

消息通知的后续演进：HTTP 与消息消费者调用同一个同步器。广播不能误配成只让一个消费者处理的共享消费组。若需要可靠事件投递，可把发布记录与 Outbox 事件写入同一数据库事务，由分发器重试发送；实例仍保留周期补偿，处理重复及乱序事件。

当前 Mastra 能力核对与限制
  • 核对版本：@mastra/core 1.74.0、Mastra CLI 1.32.1，依据本地包文档与 .d.ts。正式实施前重新确认锁定版本与存储适配器。
  • createTool() 返回 Tool 对象；Agent 的 tools / workflows 可动态解析；skills 支持按 RequestContext 解析。
  • addAgent() / addTool() / addWorkflow() 是运行时注册接口；它们不会自动实现多实例配置广播与企业发布治理。
  • addDynamicWorkflow() 是 Beta，可加载受支持 JSON 流程；持久化及重启恢复要求适配器支持 workflowDefinitions 存储域。首期优先绑定已部署工作流，动态编排另做验证。
  • 平台清单与 Mastra 动态流程定义须明确唯一管理入口，避免启动自动恢复、平台同步器和 Studio 编辑互相覆盖。同一版本的对象及绑定只由发布服务控制。
  • 本次仅编制设计文档，未实现 HTTP 接口、数据库表、同步器或运行时发布验收。

实际运行验收项 待执行

  • 发布 R8 后，进程启动标识未变化，运行对象已加载。
  • HTTP 通知断开后，周期同步仍能发现并加载 R8。
  • 重复通知不会重复构造已就绪对象或触发生效切换。
  • 加载中断后可重试；半成品对象无法被业务入口使用。
  • 网关未就绪时 R8 不生效，当前 R7 请求正常执行。
  • 切换后新运行使用 R8，已有 R7 运行保持版本一致。
  • 迟到 R8 通知不能覆盖已经生效的 R9。
  • 回退会增加 generation，并保留操作与加载审计。
  • 实例重启后 bootId 改变，旧 READY 作废并重新同步。
  • 新增第二实例后无需再次人工发布即可加载应服务版本。
  • 有权 / 无权用户的真实目标系统查询结果符合权限范围。
  • 工具调用审计关联用户、runId、releaseId、工具版本和目标系统。
  • 目标凭据不进入模型参数、工具定义、模型结果或普通日志。
  • 若启用持久化流程，重启后能按原版本恢复并保留依赖。

实施前需确定的参数

首个目标系统及用户委托方式；发布与运行存储选型；实例标识和发现方式；首期服务范围；同步间隔、心跳超时及加载超时；生效操作权限；版本及挂起运行留存期；是否启用 Beta 动态工作流。以上参数由实际部署与业务要求确定，本文不预设已验证。
